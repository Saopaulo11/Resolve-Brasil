# Resolve Brasil

Каркас нового проекта: Next.js 16 (App Router) и Supabase. Продуктового кода
здесь пока нет — только то, без чего нельзя начать: клиенты Supabase, обновление
сессии, диагностика стенда и миграции в репозитории.

Проект живёт в отдельном репозитории и ничего не наследует от JimoTrust/BitTroca:
общей истории, общего CI и общих прав доступа у них нет.

## Быстрый старт

```bash
npm install
cp .env.example .env.local   # и заполнить два обязательных значения
npm run dev                  # http://localhost:3000
```

Главная страница показывает живой ответ `/api/health`: видит ли приложение
Supabase и читается ли база. Пока ключи не заданы, там будет красное «не
задана» — это нормально и именно так и задумано.

## Переменные окружения

| Переменная | Обязательна | Что это |
| --- | --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | да | `https://<ref>.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | да | публичный ключ; попадает в браузер, доступ ограничивает RLS |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | нет | старое имя того же ключа, читается как запасное |
| `SUPABASE_SECRET_KEY` | нет | обходит RLS целиком; только для серверных задач |
| `DATABASE_URL` | нет | нужен только Supabase CLI для миграций |

Подробности и предостережения — в `.env.example`.

Ключи читаются лениво (`src/lib/supabase/env.ts`), а не на уровне модуля.
Поэтому `npm run build` проходит без них: на Vercel они есть, а в CI — нет, и
сборка там всё равно обязана проходить.

## Что где лежит

| Путь | Зачем |
| --- | --- |
| `src/app/page.tsx` | страница-заглушка со статусом подключения |
| `src/app/api/health/route.ts` | `200`, если база читается, иначе `503` с причиной |
| `src/lib/supabase/server.ts` | клиент для Server Components, Route Handlers, Server Actions |
| `src/lib/supabase/client.ts` | клиент для браузера |
| `src/lib/supabase/env.ts` | ленивая проверка ключей |
| `src/proxy.ts` | обновление сессии Supabase до рендера |
| `supabase/migrations/` | схема базы в репозитории |

## Чем эта версия Next.js отличается

В Next.js 16 **middleware переименован в proxy**: файл называется `proxy.ts` и
лежит рядом с `app/`, то есть в `src/proxy.ts`. Документация Supabase всё ещё
показывает `middleware.ts` — такой файл в этой версии просто не вызовется, и
сессия молча перестанет обновляться.

Сборщик по умолчанию — Turbopack. Актуальные руководства лежат прямо в дереве:
`node_modules/next/dist/docs/` (см. `AGENTS.md`).

## Миграции

SQL лежит в `supabase/migrations/` и является источником правды: менять схему
только файлом, иначе облако и репозиторий разъедутся.

```bash
npx supabase link --project-ref <ref>
npx supabase db push
```

## Деплой

Функции Vercel считаются в `gru1` (Сан-Паулу) — это задано в `vercel.json`.
База Supabase тоже в Сан-Паулу (`sa-east-1`): смысл именно в том, чтобы функция
и база стояли рядом, иначе каждый запрос к базе платит за перелёт через
океан. Менять один из двух регионов в отрыве от другого не стоит.

На Vercel нужны те же переменные, что и локально:
`NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Обе — с
префиксом `NEXT_PUBLIC_`, значит подставляются в бандл на сборке: после их
изменения нужен новый деплой, перезапуска мало.

Проверка развёрнутого стенда — `/api/health`: `200` означает, что функция
действительно дочитывается до базы, а не просто отвечает.
